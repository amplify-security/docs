## What it's for

Bringing Amplify Console to where your team already talks. With the app installed:

- **People chat with the agent from Slack.** A direct message to Amplify Console gets the same agent you use
  in [chat](/interactive/chat) in the web console, with the same tools and the same access to your
  organization's projects and findings.
- **The agent answers @-mentions** in channels an admin chooses, replying in a thread the channel can see.
- **Workflows post their results to a channel** through the **Slack message** [output](/workflows/outputs).
- **Agents can post, reply, and react in Slack** as the Amplify Console bot, in chat and in workflow steps.

Everything the app does in Slack appears as **Amplify Console**, the app's own bot user. There is no Slack
account for you to create or manage.

## Before you install

- **A Console organization admin installs it.** Installing starts from the Connections page, which only
  admins can change.
- **The installer must be allowed to add apps to the Slack workspace.** If your workspace requires admin
  approval for apps, the install pauses on a Slack approval request. A Slack admin can approve it from
  **Admin → Apps → Requests to install**, or pre-approve it ahead of time with an app-approval rule for app ID
  `A0C28V9SYJK` (Amplify Console).
- **Slack's agent experience needs a paid Slack plan.** The Agents surface in Slack, where people open a
  conversation with Amplify Console, is a feature of Slack's paid plans.

<Note>
  Amplify Console is not yet listed in the Slack Marketplace. Install it from the Connections page in Console,
  as described below.
</Note>

## Installing

1. On **Connections**, click **Add connection**.
2. Expand **Agent Tools** and choose **Slack**.
3. Click **Add to Slack**. Slack's authorization page opens for the workspace your browser is signed into.
4. Review the permissions and approve. Slack returns you to **Connections**, where the workspace now has a card.

The person who installed the app gets a welcome message from Amplify Console in Slack.

One Console organization can install the app into more than one Slack workspace. Each workspace gets its own
card. An Enterprise Grid installation shows one card listing each workspace it covers and its status.

## Who can talk to the agent

A person in Slack can use the agent only if their Slack account's email address matches the email of an
Amplify Console account that is a member of the organization that installed the app. The email must be
confirmed in Slack.

Anyone else who messages or mentions the agent gets one reply asking them to sign in to Amplify Console with
that Slack email address, and nothing else happens. Slack guests can't use agents at all.

The agent acts as the matched Console member. It sees what that member could see in Console, and the
conversation is saved under their account.

## Direct messages

Open **Amplify Console** from the Agents surface in Slack and send a message. The agent shows that it's
working, streams its answer into the conversation, and ends with an **Open in Console** link to the same
conversation in the web console.

- **Each thread is one conversation.** Replies in the same thread continue it; a new thread starts a new one.
- **You can stop a reply.** Use Slack's stop control while the agent is working. The reply ends with
  *Stopped.*
- **Titles stay in sync.** The agent names the conversation after its first turn. Renaming it in Slack renames
  it in Console.
- **Suggested prompts** appear when you open the agent, to get started.

## Channel @-mentions

The agent answers @-mentions only in channels an organization admin has chosen. Until an admin chooses some,
it ignores mentions everywhere.

To choose channels, on **Connections**, click **Channels** on the Slack workspace's card, select the channels,
and click **Save**. Only public channels can be chosen. The Amplify Console bot joins each channel you add.

When someone in a chosen channel mentions **@Amplify Console**:

- The agent replies in a thread under the mention, addressed to the person who asked.
- **The reply is visible to everyone in the channel.** Don't ask about anything in a channel that the channel
  shouldn't see.
- The agent answers from the text of the mention. It doesn't read the rest of the channel or the thread, so
  put what it needs in the message.
- The same identity rule applies: only people who match a Console member of your organization get an answer.

## Posting workflow results to a channel

Add a **Slack message** output to a workflow to post a summary of each completed run to a channel: the run's
outcome, counts by severity, the top findings, and an **Open run** link. In the workflow editor's **Output**
section, add the output, then pick the Slack workspace and the channel.

The bot can post to any public channel. For a private channel, invite **@Amplify Console** to it first.
See [outputs](/workflows/outputs#slack-message) for how outputs are dispatched and how to check delivery.

## What agents can do in Slack

Once a workspace is installed, every agent in your organization gets these tools, in chat and in workflow
steps. Everything they post appears as **Amplify Console**.

| Tool | What it does |
| --- | --- |
| `slack_post_message` | Posts a message to a channel or conversation, optionally as a reply in a thread. |
| `slack_read_thread` | Reads the replies in a thread the bot started or was mentioned in. |
| `slack_get_permalink` | Returns a permanent link to a message. |
| `slack_add_reaction` | Adds an emoji reaction to a message. |

In a direct message, the agent posts into a channel only when you explicitly ask it to.

## What agents can't do

- Read channel history, or any thread the bot didn't start and wasn't mentioned in
- Edit or delete messages, or remove reactions
- Create channels, invite or remove members, or change any workspace or channel setting
- Fetch files or links shared in a message
- Answer @-mentions in channels an admin hasn't chosen, or in private channels

## What Amplify stores

- **Conversations are kept as Console chat transcripts.** Each Slack conversation with the agent is saved as a
  chat session owned by the person who started it, with their messages and the agent's replies. They can
  reopen it in Console.
- **Other Slack content is processed, not kept.** Message text is used to answer, and Amplify stores only the
  identifiers that link a Slack thread to its Console conversation: workspace, channel, and thread.
- **Answers are generated by AI and can be wrong.** Every reply ends with a note that it was generated by an
  Amplify Console agent.

## Disconnecting

On **Connections**, click **Disconnect** on the Slack workspace's card and confirm. The agent stops
responding in that workspace, open conversations are closed, and Amplify revokes its Slack token. An
organization admin can do this. The transcripts already saved in Console are kept.

A Slack admin can also remove the app from Slack's side, under **Manage apps → Amplify Console → Remove**.
The agent stops responding there too.
